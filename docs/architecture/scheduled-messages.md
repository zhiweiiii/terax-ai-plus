# 定时消息

`ScheduleButton` 分别选择执行模式与时间规则，Rust `schedule.rs` 每秒检查到期任务。桌面使用 `schedule_add_at`，手机保留兼容的 `schedule_add` 终端延时接口。

- 终端：按 leaf 绑定，写入消息和 CR；关闭对应终端或重启应用后保留并暂停任务，需在桌面手动绑定当前终端。已过期任务的恢复按钮明确提示立即发送。
- Codex：独立无窗口 `codex exec --skip-git-repo-check --color never -`。
- Claude Code：独立无窗口 `claude -p --output-format text`。

后两种由 `schedule/background.rs` 管理，消息通过 stdin 传递并关闭输入，不拼接到 shell 命令。不新建 PTY，不需要用户选择工作目录，内部固定使用 app-local-data 下的 `scheduled-agent`。每次新建对话，沿用本机 CLI 的登录、默认模型及用户配置，不增加跳过权限检查参数。CLI 未安装、未登录、无网络或权限不足时，结果显示失败。

后台最多并行四个，队列等待不消耗后台进程；每项运行标记避免重复触发。stdout/stderr 持续读取但各最多保留 16 KiB，避免管道阻塞和内存无限增长。Windows Job Object 负责退出、取消及 30 分钟超时的子进程树清理。取消执行中任务后不能撤回已经发送给服务商的请求。

每日 HH:mm 按本机时区算下一次，而非固定增加 24 小时；错过的待执行任务恢复后执行一次，不补发积压的所有天数。单次任务保留完成状态和结果，每日后台任务保留最近结果。不支持关机或应用未运行时执行。

## 持久化与恢复

`schedule/storage.rs` 将任务存入 Tauri app-local-data 目录的 `schedules.json`，开发版使用 `schedules-dev.json` 隔离。文件含版本、任务内容、目标、时间、暂停/运行/完成状态和最近执行结果，均为本机明文，勿把密钥直接放在消息里。

新增、取消、绑定和执行状态变化持有同一队列锁串行保存，临时文件 flush + sync_all 后原子替换；无变更不写盘。新增和取消写入失败会回滚并报错；其他存储错误暂停自动调度，面板显示错误。读取错误、未知版本或损坏文件不会被空队列覆盖。持有不共享的 Windows 锁文件句柄，避免第二个同类型实例执行同一批任务。

调用 CLI 或写入终端前先保存 running。上次退出时 running 的单次任务标记为中断、结果未知，不自动重发；每日任务记录中断并安排下一次。无法把远程模型请求与本地文件做原子事务，因此宁可不重试不确定结果，不承诺恰好执行一次。重启时终端 leaf 不能证明是原会话，未完成终端任务一律暂停，手动绑定后才恢复。

## 发布前竞态复核（2026-10-02）

终端发送复用 `Session::web_submit` 的校验、去重与提交逻辑。Codex 使用 bracketed paste 边界后发送 CR，其他程序保持文字加 CR；编号包含任务 ID 和本次 fire_at，每日任务不会复用前一天编号。成功结果是“已发送到终端”，只证明 PTY 写入和 flush 成功，不证明命令执行成功。发送失败与终端激活超时写入最近结果，不再只有“已结束”而没有原因。

扫描得到的到期列表只是快照，执行前再次校验 running/paused/finished、触发时间和终端绑定；结束时也核对本次触发身份。重新绑定后，旧快照与旧失败结果不能结束新绑定的任务。过期任务重新绑定将 fire_at 推进至当前时刻，重新获得完整 60 秒终端激活窗口；未到期时间保持不变。

绑定实现位于 ScheduleState，IPC 只调用状态方法和发事件。保存失败恢复原绑定、暂停状态、时间和最近结果，同时暂停调度；完成的单次任务不会残留“待绑定”状态。删除了另一个直接写入终端的实现和不再使用的 ENTER 常量。

桌面面板保存期间保留后来输入的草稿，提交成功只清空仍与原提交一致的字段。同步 busy ref 阻止重复提交；列表响应按请求代次应用，实时任务或错误事件作废旧读取结果，避免覆盖更新后的列表和错误状态。
